## 1. OpenCode 맥 설치 방법 — 확인함

- 공식 문서 첫 화면(V2, latest)의 설치 방법
  - `curl -fsSL https://opencode.ai/v2/install | bash`
  - Homebrew : `brew install anomalyco/tap/opencode-v2`
  - npm : `npm install -g @opencode/cli`
  - 출처 : https://opencode.ai/docs (https://opencode.ai/docs/index.md)
- 설치 프로그램 내용 (https://opencode.ai/v2/install 직접 받아 읽음)
  - `https://opencode.ai/update/api/latest/cli/npm` 에서 최신 버전 확인 → 2026-11-19 기준 `2.3.2`
  - 설치 위치 `~/.opencode/bin/opencode`, 옵션 `--no-modify-path`, `--version`
  - PATH 는 셸 설정 파일(`~/.zshrc` 등)이 **이미 있을 때만** 추가한다 → 새 맥은 `~/.zshrc` 가 없을 수 있어서 install.sh 가 먼저 빈 `~/.zshrc` 를 만든다
- 구 주소 `https://opencode.ai/install` 은 npm `opencode-ai`(1.19.6) / GitHub `v1.x` 태그를 설치 → 구버전
- 1.x 문서 : https://opencode.ai/v1/docs/cli

## 2. OpenCode API 키 저장 위치 · 형식 — 확인함 (버전별로 다름)

- **1.x** : `~/.local/share/opencode/auth.json`, 형식 `{"anthropic":{"type":"api","key":"..."}}` — 지시서 가정이 맞음
  - 출처 : https://opencode.ai/v1/docs/cli ("This is stored in ~/.local/share/opencode/auth.json")
- **2.x** : 키는 서버의 SQLite DB(보통 `~/.local/share/opencode/opencode.db`)에 저장. "Do not edit the database to manage credentials; use /connect or the auth commands."
  - 출처 : https://opencode.ai/docs/cli/providers (Storage 절)
  - auth.json 은 DB 마이그레이션 때 한 번만 가져온다("V2 imports supported credentials from the legacy auth.json … during its database migration. New and updated credentials are stored in SQLite rather than written back to that file.")
  - 소스 : https://github.com/anomalyco/opencode/blob/dev/packages/core/src/database/migration/20260805200742_import_legacy_credentials.ts
- 2.x 에서 키를 비대화식으로 넣는 방법
  - `opencode auth login anthropic --method key` 는 **대화형 터미널이 필요**(문서 : "API-key entry and provider forms require an interactive terminal")
  - `opencode auth import` : `auth export` 형식(JSON 배열)을 **표준입력**으로 받아 등록 — 키를 명령줄 인자·파일에 남기지 않을 수 있어 이 방식을 쓴다
    - 형식 : `[{"id":"cred_…","integrationID":"anthropic","label":"…","active":true,"value":{"type":"key","key":"…"}}]`
    - 같은 공급자에 다른 키가 이미 있으면 새 키를 활성화하지 않으므로 `opencode auth switch anthropic <id>` 로 전환
    - 소스 : `packages/cli/src/commands/handlers/auth/import.ts`, `switch.ts`, `logout.ts`, `packages/schema/src/credential.ts`
  - `opencode service set env ANTHROPIC_API_KEY …` 도 있으나 키가 명령줄 인자로 드러나서 쓰지 않음
- 2.x 웹 화면 (지시서 2-2 의 7번 관련)
  - 웹 UI 는 공용 백그라운드 서비스가 제공, 비밀번호 보호. 맥 기본 포트 49374. `opencode pair` 가 1회용 링크(5분 유효)를 출력하고 끝나며, 링크로 들어가면 세션 쿠키 30일 유지
  - `opencode service start` 는 서비스를 띄우고 주소만 출력한 뒤 끝남
  - 출처 : https://opencode.ai/docs/cli/web , https://opencode.ai/docs/cli , 소스 `packages/cli/src/commands/handlers/pair.ts`, `service/start.ts`
- 2.x 를 이 컨테이너에서 직접 실행해 보지는 못했다(보안 정책으로 내려받은 실행 파일 실행 불가) → 맥 CI(GitHub Actions)에서 실제 설치·등록·삭제를 검사

## 3. Anthropic 비용 조회 API — 확인함

- 권장 : **Usage and Cost Analytics API** (베타)
  - `GET https://api.anthropic.com/v1/organizations/analytics/cost`
  - 헤더 : `x-api-key: <관리자 키>`, `anthropic-version: 2026-10-21`, `anthropic-beta: analytics-usage-cost-2026-08-24` (베타 헤더가 없으면 404 또는 권한 오류)
  - 출처 : https://platform.claude.com/docs/en/manage-claude/usage-cost-analytics-api
- 구형 : `GET /v1/organizations/cost_report` (계속 지원되지만 legacy, 하루 단위, 마지막 UTC 자정까지만)
  - 출처 : https://platform.claude.com/docs/en/manage-claude/usage-cost-api — "오늘 사용액(달러)은 `/analytics/cost` 로만 볼 수 있다"
- 요청 규칙
  - `starting_at` 필수, 2026-01-01 이후 · 최근 365일 이내, 한 번에 최대 31일
  - `time_bucket_width` = `1m` / `1h` / `1d`, 지정하면 `ending_at` 필수. `limit` 최대 1000행
  - 양 끝은 UTC 버킷 경계로 내림. 이 키트는 `1h` 버킷으로 받아 **사용자 컴퓨터 현지 시각**의 오늘/이번 주(월요일 시작)/이번 달로 합산
- 응답 형식
  ```json
  { "data": [ { "starting_at": "…", "ending_at": "…", "group": { … },
                "cost": { "currency": "USD", "amount": "41280.000000", "list_amount": "…", "requests": 3 } } ],
    "has_more": false, "next_page": null, "data_refreshed_at": "2026-09-18T16:02:11Z" }
  ```
  - `amount` 는 **센트 단위 문자열**(소수 6자리), 할인 후·크레딧 차감 전 금액
- 반영 지연 : 보통 **4시간 안**, 최대 **24시간**. `data_refreshed_at` 이후는 비어 있거나 일부. 데이터가 하나도 없으면 `data_refreshed_at: null`, `data: []`
  - 팝업에 "○○까지 반영 · 보통 4시간(최대 24시간) 늦게 반영"을 함께 표시
- 개인(Individual) 콘솔 계정과 claude.ai Team 요금제 조직은 Admin API 를 못 쓴다(먼저 Organization 설정 필요)

## 5. API 키 유효성 확인 요청 — 확인함

- `GET https://api.anthropic.com/v1/models` + `x-api-key` + `anthropic-version: 2026-10-21` → 정상 키면 200
  - 출처 : https://platform.claude.com/docs/en/api/models/list
- 이 세션에서 실제 확인 : 가짜 키로 요청 → **401**(authentication_error) 응답 → install.sh 가 "키 오류"로 안내 (`tests/sim/interactive-sim.py`)
- 오류 구분 (출처 : https://platform.claude.com/docs/en/api/errors)
  - 401 `authentication_error` → 키 오류 / 403 `permission_error` → 키 권한 문제
  - 402 `billing_error` → 결제·잔액 문제
  - 400 + "not scoped to a workspace" → 작업 공간을 지정하지 않은 개인 키 (https://platform.claude.com/docs/en/manage-claude/authentication)
  - 429 / 500 / 529 → 일시적 문제, 연결 실패(HTTP 000) → 인터넷 문제
- 키 헤더 : 표준은 `Authorization: Bearer`, `x-api-key` 는 구형이지만 계속 지원(같은 문서). OpenCode 2.x 도 `x-api-key` 로 보낸다(소스 `packages/ai/src/providers/anthropic.ts`) → 키 확인도 같은 방식
- 키 접두어 : 문서는 "`sk-ant-` 로 시작"이라고만 한다. 예전(작업 공간) 키는 `sk-ant-api…`, **사람에게 연결된 개인 키는 `sk-ant-usr…`** (2026-11-19 사용자가 실제로 받은 키로 확인). 설치 프로그램은 `sk-ant-` 로 시작하면 받고(관리자 키 `sk-ant-admin…`, Claude Code 로그인 토큰 `sk-ant-oat…` 은 따로 안내), 실제 확인은 서버 응답으로 한다
- API 키 만드는 곳 : `platform.claude.com/settings/keys` → **Create key** → 이름 · 만료 · Linked account · (Workspace) → 한 번만 보이는 키 복사
  - 출처 : https://platform.claude.com/docs/en/get-api-key
- **미확인** : 잔액이 0 일 때 `/v1/models` 가 402 를 주는지(목록 조회는 과금이 없어 200 일 가능성이 큼). 이 경우 설치 때는 "잔액 없음"을 알 수 없고, 확장의 잔액 표시로 확인한다

## 추가로 확인한 것

- **브라우저(확장)에서 직접 API 호출** : `Origin` 헤더가 붙는 요청은 `anthropic-dangerous-direct-browser-access: true` 헤더가 있어야 받는다. ZDR(데이터 미보관)·Compliance API 가 켜진 조직은 이 헤더가 있어도 401 "CORS requests are not allowed for this Organization" — 브라우저에서는 방법이 없다
  - 출처 : https://platform.claude.com/docs/en/manage-claude/authentication (Browser-based applications), https://platform.claude.com/docs/en/api/errors
  - 확장은 이 헤더를 보내고, 해당 401 은 따로 안내한다. **미확인** : 관리자 키 + 분석 API 가 이 헤더로 실제 200 을 주는지(실제 관리자 키 필요)
- **맥 기본 bash 는 3.2** : install.sh 는 bash 3.2 문법만 쓴다(연관 배열·`${var,,}`·`mapfile` 없음). CI 에서 `/bin/bash` 로 실행
- **curl | bash 와 입력** : 표준입력이 스크립트이므로 모든 입력은 `/dev/tty`, 키는 `read -s`. 키를 curl 에 넘길 때도 명령줄 인자 대신 `curl -K -`(표준입력 설정)로 넘긴다
- **JSON 처리** : `osascript -l JavaScript`(JXA)만 사용. python3 는 쓰지 않음(개발도구 설치 창 문제)
- **크롬 확장 화면의 한국어 버튼 이름** (2026-11-19, 한국어 크로미움으로 직접 확인) : 「개발자 모드」, **「압축해제된 확장 프로그램 로드」**(지시서의 "…을 로드합니다"는 예전 이름). 안내서 그림 `manual/img/ext-*.png` 는 이 화면을 찍은 것
- **확장 등록 자동 확인** : 압축해제 확장의 ID 는 폴더 경로의 SHA-256 앞 32자를 a~p 로 바꾼 값이고(실제 ID 와 대조해 확인), 크롬은 프로필의 `Preferences` 에 `"path":"<폴더>"` 와 `"<ID>":{…}`, 툴바 고정은 `"pinned_extensions":[…]` 로 남긴다. install.sh 는 이 파일을 **읽기만** 해서 "크롬에 잘 들어갔어요 / 고정됐어요"를 확인한다(못 찾으면 넘어갈 수 있음)
